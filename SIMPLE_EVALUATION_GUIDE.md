# Simplified evaluation workflow

1. Reload the unpacked extension, reopen the dashboard and side panel.
2. Once per study, save the annotator/rubric IDs and the actual protocol evidence. New saves use `rq1-simple-v2`; existing seals are not migrated or retrospectively certified. Use Revise as unsealed draft to start the revised protocol. Do not tick unfinished checks.
3. Before a page's first scan, register its ID, URL, split, label and one-sentence evidence-based reason. Blank group generates `GROUP-<case ID>`; manually reuse the parent group for variants/duplicates. This default is not an independence audit. Record capture/construction/parent provenance once.
4. Scan the page. Edit its case to mark extraction Correct, Partial or Incorrect; describe problems only when needed. Check actual target content, not merely the program's OK status. Old labels/reasons retain their timestamps; a reason added after exposure is flagged late.
5. On each registered page in the preselected timing subset, open Research test page in the side panel and click Measure speed. Keep the same page and tab active. One batch attempts two warm-ups plus ten measured local-only scans and retains failed runs. A page or tab change stops the batch. JSON includes the batch ID, run number, phase and extension version. In `rq2Summary.timing.localEndToEnd`, median and p95 use successful measured batch runs, reduced to one median per scenario. Failures remain in the export and must be reported alongside timing.
6. Export JSON (complete analysis input) and CSV (summary). Export frequently: bounded history retains at most 500 successful records and 500 failure records, each at most 30 days. Twelve scans per page can fill history quickly; combine exports by attempt ID without double counting.

New fields include reason/time/blinding status, extraction review/notes, provenance reference, batch/run/phase, extraction time, local end-to-end time and extension version. Local end-to-end runs from scan-handler entry through completed local scoring, including setup and messaging but excluding corroboration and final record persistence. Total latency may include backend; scoring latency measures only scoreAll. Existing JSON records are not retroactively populated with new measurements.

Per-case overlap is optional under simple-v2. A study-level rubric/rule relationship and shared-author bias record remains required. The Python RQ1 path accepts simple-v2 without lower-overlap gates, retaining group/class support, seal, provenance, sensitivity, precision and conformance checks. This revised method must also be reflected in the thesis. Timing summaries remain scenario-level operational diagnostics; manual extraction reviews are exported separately and do not silently replace technical success rates. Source composition must be interpreted from the provenance register; absence of real Elevated evidence cannot be repaired by relabelling synthetic pages.
